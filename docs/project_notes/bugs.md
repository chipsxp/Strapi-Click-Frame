### 2026-05-25 - Persistent Logout / Sticky Session

- **Issue**: User remains logged in even after clicking "Log Out" in the dashboard.
- **Root Cause**: Potential race condition between fetch-based logout and client-side navigation, combined with aggressive browser/proxy caching of the JWT cookie.
- **Solution**: (1) Switched dashboard logout to a direct `<a>` link to `/api/logout` to force a full browser navigation; (2) Refactored `middleware.ts` to inject `Cache-Control: no-store, no-cache, must-revalidate, max-age=0` on ALL responses; (3) Synchronized cookie attributes (path, secure, sameSite) between login and logout logic.
- **Status**: Diagnostic changes staged.

### 2026-05-25 - Build Timeout: Railway Content Sync (Hybrid Cloud Latency)

- **Issue**: `railway up` failed during `npm run build` because the Astro content sync phase timed out (10s default) while fetching data from the external Strapi Cloud instance.
- **Root Cause**: Astro content loaders perform network requests at build-time. Latency between Railway (Builder) and Strapi Cloud (Server) can intermittently exceed 10s, especially during cold starts or high traffic.
- **Solution**: Refactored `react/src/content.config.ts` with a `fetchWithRetry` utility featuring exponential backoff and a 30-second timeout.
- **Prevention**: All build-time network requests must implement retries and generous timeouts (30s+) to account for hybrid cloud networking overhead.

### 2026-05-14 - Email Verification Link Mismatch (confirm_token vs confirmationToken)

- **Issue**: Users remain unconfirmed (`confirmed: false`) even after clicking the email verification link. The link would redirect to the success page but the database remained unchanged.
- **Root Cause**: The custom user schema extension in `src/extensions/users-permissions/content-types/user/schema.json` used snake_case field names (`confirm_token`, `registration_token`, `reset_password_token`). However, the Strapi `users-permissions` plugin's internal logic explicitly expects CamelCase names (`confirmationToken`, `registrationToken`, `resetPasswordToken`). In Strapi 5, this mismatch caused the plugin to fail finding the user by token or updating the record, often failing silently while still performing a 302 redirect.
- **Solution**: Renamed the attributes in `schema.json` to CamelCase. Strapi automatically updated the database columns to `confirmation_token`, etc., upon restart. Verified that tokens are now correctly generated and cleared during registration and confirmation.
- **Prevention**: When extending the `users-permissions` plugin's user schema, **NEVER** rename standard field names to snake_case. Always stick to the standard CamelCase attributes (`confirmationToken`, `resetPasswordToken`, `registrationToken`) to ensure compatibility with the plugin's internal controllers and services.

### 2026-04-27 - `astro:content` Cannot Be Found (TypeScript)

- **Issue**: Editor and `astro check` report `Cannot find module 'astro:content'` on all imports in `content.config.ts`, `index.astro`, and `blog/[slug].astro`
- **Root Cause**: Two missing pieces: (1) `react/.astro/types.d.ts` is auto-generated by Astro on first `astro dev` run — it did not exist yet; (2) `react/src/env.d.ts` with `/// <reference types="astro/client" />` was missing, so TypeScript had no fallback type source
- **Solution**: Created `react/src/env.d.ts` with `/// <reference types="astro/client" />`. Running `astro dev` then generates `react/.astro/types.d.ts` permanently
- **Prevention**: Always create `src/env.d.ts` when scaffolding a new Astro project; commit it so future clones don't hit this before first dev run

### 2026-04-27 - Single Type Collections Return 404 (`/api/globals`, `/api/abouts`)

- **Issue**: Astro dev server logs `Request failed with status code 404 Not Found: GET http://localhost:1337/api/globals?populate=*&pagination...` for `global` (and would also 404 for `about`)
- **Root Cause**: `strapi-community-astro-loader` v4 only supports Strapi **collection types** — it calls `@strapi/client`'s `client.collection(pluralContentType)` internally, which paginates and uses the plural name. Strapi **single types** (`about`, `global`) live at singular endpoints (`/api/about`, `/api/global`) and return one object, not a paginated array
- **Solution**: Wrote a custom `strapiSingleLoader` function in `react/src/content.config.ts` that fetches the singular endpoint via `fetch()`, reads `json.data`, and calls `store.set({ id: documentId, data })` once. `about` and `global` collections now use this loader
- **Prevention**: Any Strapi single type must use a custom loader or direct `fetch()` call — do not pass them to `strapiLoader()`

### 2026-05-03 - ImageKit Plugin 500 Internal Server Error

- **Issue**: Astro build failed with 500 Internal Server Error when fetching `/api/global`, `/api/about`, and `/api/categories`.
- **Root Cause**: The `strapi-plugin-imagekit` requires its API credentials under a specific `imagekit` key in `config/plugins.ts`. While upload provider credentials were set under `upload`, the standalone plugin initialization crashed the server on endpoints containing media fields because it couldn't find the `imagekit` block. Furthermore, the `photorium/.env` file became corrupted with mixed UTF-8 and UTF-16LE encodings when keys were appended via PowerShell, causing Node.js to treat it as a binary file.
- **Solution**: Re-encoded `.env` to pure UTF-8. Added the `imagekit: { enabled: true, config: { ... } }` block to `photorium/config/plugins.ts`.
- **Prevention**: When installing Strapi plugins, always verify if they require a top-level configuration block in `plugins.ts` in addition to the standard `upload` provider block. Ensure `.env` file appends preserve UTF-8 encoding.

### 2026-05-17 - Invalid populate parameter Error (Strapi 5.46)

- **Issue**: Backend returns 400 Bad Request with "Invalid populate parameter. Expected a string, an array of strings, a populate object" in `convertPopulateQueryParams`.
- **Root Cause**: Strapi 5.46 introduced stricter validation in the Document Service's query transformation. Specifically:
  1. **Mixed-Type Population**: Query strings that combined a wildcard (`populate=*`) with specific nested population (`populate[field][populate]=*`) resulted in a mixed array (`['*', { field: { populate: '*' } }]`) that caused an internal `.flatMap()` crash.
  2. **Empty Arrays**: Passing `populate: []` (empty array) to the Document Service now triggers a validation error instead of being silently ignored.
  3. **Syntax Mismatch**: Some Document Service methods in 5.46 are highly sensitive to the difference between string arrays (`['role']`) and objects (`{ role: true }`).
- **Solution**:
  1. **Unified Syntax**: Refactored the global layout fetch to use a single indexed array format: `?populate[0]=defaultSeo&populate[1]=favicon&populate[defaultSeo][populate]=*`. This avoids mixing string wildcards with objects.
  2. **Defensive Helpers**: Refactored backend helpers (like `findDoc` in reaction lifecycles) to only include the `populate` key if it contains data, avoiding empty array errors.
  3. **Object-Based Default**: Standardized on object-based population (`populate: { author: true }`) for internal `strapi.documents` calls for maximum resilience.
- **Prevention**: In Strapi 5.46+, avoid mixing `populate=*` with other `populate[...]` parameters in the same URL. Always ensure population parameters passed to the Document Service are non-empty and prefer object syntax for nested relations.

### 2026-05-17 - Strapi 5 Relation Error (Internal Server Error on Comment POST)

- **Issue**: Posting a comment or reply returned a 500 Internal Server Error from the API.
- **Root Cause**: Strapi 5's REST API and Document Service have transitioned to using **Document IDs** (strings like `abc123...`) for all relational assignments. The frontend was mistakenly sending numeric `id` values for the `photo`, `author`, and `parent` relations. Furthermore, the `data` payload for relations often requires an explicit `connect` or `disconnect` object in recent Strapi 5 versions (e.g., `{ photo: { connect: ["doc-id"] } }`).
- **Solution**: Updated the `/api/comment` route and `CommentSection.tsx` to pass `documentId` instead of `id`. Refactored the payload to use the `connect` syntax: `photo: { connect: [photoId] }`.
- **Prevention**: In Strapi 5, always use `documentId` for linking relations via REST. For critical relations, wrap the ID in an object using the `connect` key to ensure compatibility with Strapi's relation manager.

- **Prevention**: Always apply `box-sizing: border-box` at the root level of a project. When creating vertical "content columns," ensure all tiered containers share identical width, padding, and border/shadow properties.

### 2026-05-22 - Automating Interactive CLI Prompts (Strapi Cloud Deploy)

- **Issue**: `npx strapi deploy` requires multiple interactive inputs (project name, node version, region, confirmation) which are difficult to handle via standard shell piping (`echo |`) due to the way `inquirer` handles stdin.
- **Root Cause**: PowerShell piping or simple `echo` commands often close the stdin stream prematurely or fail to trigger the prompt listener in complex CLI tools.
- **Solution**: Created a custom Node.js script (`deploy_strapi.js`) using `child_process.spawn`. This script listens to `stdout` for specific prompt strings and writes the corresponding answers to `stdin` without closing the stream, allowing for a fully automated interactive session.
- **Prevention**: Use a wrapper script with `spawn` and stream listeners for any CLI tool that lacks a "force" or "non-interactive" mode for all its prompts.

### 2026-05-22 - Astro Build Fails due to Missing Backend (Strapi Cloud)

- **Issue**: `railway up` for the Astro frontend failed during the build phase with `generate-content-types-error`.
- **Root Cause**: The `strapi-community-astro-loader` performs a "preflight" check and fetches content during the `astro build` command. If the `STRAPI_URL` is a placeholder or pointing to a non-existent instance, the build fails.
- **Solution**: Deployed the Strapi Cloud backend first, obtained the live URL, and updated the Railway environment variables _before_ attempting the final frontend build.
- **Prevention**: In headless CMS architectures (Astro + Strapi), the backend must be live and accessible before the frontend build command is executed, as content is often fetched at build-time.

### 2026-05-25 - Git Push Fails in Worktree with `connect ENOENT \\.\pipe\vscode-git-...-sock`

- **Issue**: Git push/pull from a VS Code worktree window failed with `ENOENT` while trying to connect to `\\.\pipe\vscode-git-...-sock`.
- **Root Cause**: The integrated terminal inherited stale `VSCODE_GIT_*` and askpass environment variables from VS Code. Git then tried to use a dead VS Code IPC pipe for credentials instead of a persistent credential helper.
- **Solution**: Configured Git Credential Manager globally via `git credential-manager configure` and cleared the stale `VSCODE_GIT_IPC_HANDLE`, `GIT_ASKPASS`, `SSH_ASKPASS`, and `VSCODE_GIT_ASKPASS*` environment variables before running Git.
- **Prevention**: Prefer a fresh VS Code terminal after opening a worktree, and use a wrapper like `gitfixauth.js` to run Git commands with VS Code auth variables scrubbed when the terminal session looks stale.

### 2026-06-01 - PayPal Buttons Missing (400 Bad Request)

- **Issue**: PayPal buttons were not rendering on the deployed Railway site. The network tab showed a `400 Bad Request` for `https://www.paypal.com/sdk/js?components=buttons&currency=USD`.
- **Root Cause**: The URL was missing the required `client-id` parameter. This occurred because the `PUBLIC_PAYPAL_CLIENT_ID` environment variable was not set in the Railway environment, causing the client-side component to pass an empty string to the SDK script provider.
- **Solution**: Set the `PUBLIC_PAYPAL_CLIENT_ID` variable on the Railway service and triggered a redeployment via `railway up`.
- **Prevention**: Whenever adding client-side integrations requiring public API keys, ensure the corresponding environment variables are mirrored from `.env` to all staging and production environments.
